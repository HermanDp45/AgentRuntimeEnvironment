# БАФ — базисные агентские функции

Проверяют атомарные функции пары «харнес + LLM»: чтение, поиск, создание,
редактирование, инструмент, код, рассуждение, синтез. Инфраструктура проверяется
отдельно в [tests/infra/](../tests/infra/README.md).

Курсовой набор — [catalog.yaml](catalog.yaml): 8 БАФ × 3 задачи + 3 составные.
Полностью оформлен пример [B1.1-service-port](B1-read/B1.1-service-port).
Каталог и пример перенесены без изменений из ревизии
[`b01ddf7`](https://github.com/deeppavlov/agentic-course-itmo/tree/b01ddf7b89e5c603985e3d5b5af958bebc7b1972/projects/templates/track-a-agent-runtime/baf).
Остальные задачи и раннер ещё не реализованы; своих задач пока нет.

## Формат задачи

```text
baf/<БАФ>/<задача>/
├── task.yaml    # id, baf, level, messages, timeout_s, answer_file
├── fixture/     # исходное содержимое workdir
└── check.py     # итоговое состояние → JSON {"pass": bool, "reason": str}
```

Каждый запуск начинает с чистой копии fixture. Чекер и скрытые эталоны находятся
вне рабочей папки агента. Проверяется итоговый файл, а не ответ модели в чате.
Успех определяется JSON-полем `pass`: чекер Б1.1 возвращает exit code 0 и при неверном ответе.

## Режимы прогона

| Режим | Состав | Повторы | Где |
|---|---|---|---|
| smoke-БАФ | Одна simple-задача на каждую БАФ | 1 | CI, mock/record-replay, без внешней сети |
| Полный | Все задачи курса + свои + составные | 3 | Качество и сравнение пар |

Оба режима пока недоступны. `make baf-smoke` и `make baf PAIR=<harness>+<model>`
возвращают ошибку «не реализовано».

Формат результата по шаблону: `results/baf/<pair>/<timestamp>.jsonl`.
Поля: `task_id, repeat, pass, reason, tokens_in, tokens_out, seconds, outcome`.
Рядом сохраняются конфигурация, версии и команда воспроизведения.
Собственные задачи и обоснование — в [docs/baf.md](../docs/baf.md).

Чекер Б1.1 можно вызвать отдельно: `uv run --frozen --offline python
baf/B1-read/B1.1-service-port/check.py /путь/к/итоговой/папке`.
Это проверка файла, не запуск агента и не доказательство прохождения БАФ.
