# Харнес

Реализован собственный последовательный Python-харнес. Gateway проверяет клиентский
токен; харнес обращается к модели через LLM-прокси, инструменты исполняет только
через HTTP-контракт сандбокса. Ключ модели и Docker socket харнесу не передаются.

## Один сценарий

Пользователь просит изменить note.txt. Модель вызывает read_file и получает текст
с SHA. Затем предлагает write_file: харнес повторно читает файл, сверяет SHA,
показывает diff и ждёт approval. Без него запись не отправляется в сандбокс.
После разрешения сандбокс снова проверяет SHA и атомарно заменяет файл.
Результат добавляется в контекст модели. Её текст без tool_calls завершает запуск.

Для run_command подтверждается точная строка команды, заранее предсказать её diff
нельзя. Exit code 1 — результат команды, а не ошибка связи: модель получает вывод
и может предложить следующий шаг. Новая команда требует нового подтверждения.
Отказ возвращается как approval_denied; системная инструкция запрещает обходить отказ.

## Остановка и ошибки

- Отмена прерывает запрос модели или текущую операцию; для операции клиент отправляет
  cancel в менеджер. Завершённые правки сохраняются, полного отката нет.
- При отмене оставшиеся tool_calls получают not_executed, чтобы следующая задача
  не продолжалась с незавершёнными парами assistant/tool.
- Потеря ответа exec не означает, что команда не началась: запрашивается тот же ID.
  Обрыв SSE допускает до трёх попыток продолжить наблюдение с Last-Event-ID.
  Сам exec повторно не отправляется.
- Если остановку или исход нельзя подтвердить, результат — transport/sandbox_outcome_unknown.
  Сессия блокируется для новых задач; её нужно закрыть. Это не успешная отмена.
- Обрезанный, пустой или некорректный ответ модели не считается завершением задачи.
  Превышение числа шагов/контекста возвращает отдельную ошибку limit.

## Настройки и хранение

[config.toml](../services/harness/config.toml): 20 обращений к модели, 64 операции
(включая чтение перед diff), 600 с активного времени, 60 с на модель, 120 с на инструмент,
300 с на подтверждение. Ожидание пользователя исключено из активного бюджета.
Контекст до 1 МиБ, ответ до 256 КиБ; автоматического сокращения истории пока нет.
До 4 сессий и 16 запусков на сессию, очистка после 15 минут простоя.

История и события находятся в RAM. JSONL в приватной tmpfs /runs содержит trace_id
(равен run_id), ID сессии/операции, время, вид инструмента, длительность, статус,
решение approval и usage модели. Тексты файлов, команды, diff и сообщения туда
не пишутся. Метаданные доступны через /v0/sessions/{id}/trace до закрытия сессии;
при закрытии удаляются. Это ещё не долговечная история чата и не полный replay.
После перезапуска харнеса история не восстанавливается; менеджер удалит забытые
сандбоксы по своему idle-таймеру. Проверка падения харнеса с восстановлением — C2-05.
