# ADR-0009: базовый настольный чат

- Статус: accepted для учебной фикстуры v0
- Дата: 2026-11-06
- Связано: ADR-0006/0008, C1-05b, A-2, A-7

## Контекст и решение

Студент попросил сначала видеть работу агента в чате. Ранее выбранный PySide6
используем уже сейчас: клиент обращается только к gateway по HTTP/JSON + SSE.
Команды и файлы исполняются прежними серверными компонентами.

client/gui.py содержит окно и небольшие QThread для запросов и потока событий.
GUI-поток обновляет виджеты через сигналы. client/api.py разделяет HTTP-настройки
с консолью; новый серверный API не нужен. Устанавливаем только Qt Essentials
в отдельной группе gui; контейнеры сервера не получают Qt.

Одно окно — одна временная сессия с несколькими задачами и общей историей модели.
Каждая запись/команда требует отдельного решения. Чтение выполняется автоматически.
После завершения задачи клиент получает список файлов. При обрыве SSE делает
до трёх подключений с последним sequence, без повторной отправки task/инструмента.
После неоднозначного POST task наблюдает тот же run_id, а не создаёт новый запуск.
При исчерпании попыток остаются отмена и закрытие окна.

Закрытие ждёт текущие запросы, отправляет session.close и дожидается остановки
потока, затем освобождает HTTP-клиент и QThread. Если сервер не подтвердил закрытие,
окно показывает ошибку и позволяет повторить закрытие. Принудительное завершение
приложения не гарантирует немедленную очистку: на сервере остаётся idle-таймер.

## Альтернативы

- QtNetwork: собственная асинхронная сеть Qt, но пришлось бы дублировать HTTP/SSE-код.
- asyncio внутри Qt: требует интеграции двух циклов событий и дополнительного слоя.
- Веб-интерфейс: удобен для прототипа, но меняет уже согласованный стек клиента.

## Последствия и проверка

История остаётся в RAM до закрытия; перезапуск приложения её не восстанавливает.
Нет выбора папки Mac, mount, сборки установщика и полного headless-режима.
Ответы приходят целыми сообщениями, вывод команд — событиями; токены текста
модели по одному пока не транслируются. CLI сохранён отдельно как одноразовый сценарий.

Агент проверил виджеты Qt через QtTest и mock HTTP-транспорт: подтверждение/отказ,
отмену, историю, SSE resume без повторного task, ошибку авторизации и повтор закрытия.
Проверен также GUI через настоящий HTTP gateway и Docker-сандбокс с mock LLM:
два раздельных подтверждения, diff, вывод команды, итоговый файл и очистка.
