# ADR-0004: собственный харнес и выполнение инструментов

- Статус: proposed — направление согласовано, реализация ещё не проверена
- Дата: 2026-11-06

## Контекст

Студент выбрал небольшой собственный Python-харнес, чтобы понимать весь цикл.
Открытые реализации используем для изучения, а развитие делаем постепенно.
Ориентиры: [mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent/blob/main/src/minisweagent/agents/default.py)
и [Qwen-Agent](https://github.com/QwenLM/Qwen-Agent/blob/main/qwen_agent/agents/fncall_agent.py).
Их код пока не заимствован.

## Решение

Согласовано со студентом:

- История включает сообщения пользователя, ответы модели, tool_calls и их результаты.
  Инструменты описываются отдельно; операции выполняются через протокол сандбокса.
- Чтение выполняется автоматически. Каждая запись и команда требуют подтверждения.
  Отказ пользователя возвращается модели как результат конкретного tool_call.
- Ненулевой exit code команды возвращается модели вместе с stdout/stderr.
  Модель продолжает разбор задачи; новые записи и команды требуют нового подтверждения.
- Для ЧП1 защищаем отдельную запись от прерывания. После подтверждения сохраняем
  временную копию существующего файла, записываем новую версию отдельно и заменяем
  исходник после полной записи. Перед применением проверяем актуальность исходной версии.
- Отмена останавливает выполнение, сохраняя ранее завершённые правки, включая изменения
  команд. Полного отката задачи нет. Временные копии служебные, агенту недоступны,
  в Git не попадают и удаляются после завершения операции или очистки сессии.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Готовый открытый харнес | Больше функций сразу | Дополнительный код для изучения и адаптации | Студент выбрал собственный цикл |
| Подтверждение всех инструментов | Удобно наблюдать каждый шаг | Лишние запросы на чтение | Студент разрешил автоматическое чтение |
| Остановка на каждой ошибке команды | Простое поведение | Модель не сможет разобрать упавшие тесты | Выбрано продолжение с результатом ошибки |
| Откат всех файлов задачи | Возврат к начальному состоянию | Нужно учитывать новые файлы, команды и параллельные правки | Для ЧП1 выбрана защита одной записи |

## Последствия

Прерывание записи и отмена всей задачи имеют разные гарантии. Завершённая операция
сохраняет эффект; произвольная команда не получает обещания предварительного diff.
Сбой транспорта нельзя считать обычным exit code; политика неопределённого исхода
требует проверки протокола и идемпотентности.

Предложенные начальные лимиты: 20 обращений к модели, 600 секунд активного выполнения,
60 секунд на обращение к модели, 120 секунд на команду, 300 секунд на подтверждение.
Значения должны настраиваться; конфиг и код пока отсутствуют.

Проверки перед accepted: цикл на mock LLM, отказ и одобрение, продолжение после exit 1,
лимиты, отмена, целостность файла при прерывании записи и сохранение завершённых правок.
