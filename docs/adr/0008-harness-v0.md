# ADR-0008: первый собственный харнес

- Статус: accepted для учебного сценария v0
- Дата: 2026-11-06
- Связано: ADR-0004, ADR-0006, A-4, A-6, A-7

## Контекст

Сандбокс уже исполняет типизированные операции. Студент выбрал собственный понятный
цикл, автоматическое чтение, подтверждение каждой записи/команды и завершение обычным
текстовым ответом без tool_calls. Нужен первый сквозной сценарий до GUI и mount.

## Решение

Харнес — отдельный FastAPI-сервис, как в шаблоне курса. Gateway проверяет Bearer-токен
и передаёт HTTP/SSE, харнес хранит сессии и управляет циклом. Три инструмента выводятся
из существующих моделей контракта. Их названия для модели — read_file, write_file,
run_command; после проверки они становятся ReadFile, WriteFile, RunCommand.
Несколько tool_calls одного ответа исполняются последовательно.

Для write_file харнес читает файл и сверяет ожидаемый SHA до показа diff. Approval
разрешает только подготовленную операцию с её UUID; содержимое нельзя подменить
в сообщении approval. Сандбокс повторно проверяет SHA непосредственно перед заменой.
WriteFile наследует модель ReadFile, поэтому политика определяется явным kind,
а не isinstance(ReadFile). Отказ — tool-ответ; ошибка команды тоже возвращается модели.

Каждый запуск получает run_id. Повтор того же task возвращает прежний запуск,
другое тело с тем же ID отклоняется. Потеря POST/потока сандбокса восстанавливает
наблюдение по тому же operation_id; новое исполнение автоматически не создаётся.
При неподтверждённой остановке итог transport/sandbox_outcome_unknown, сессия
блокируется для новых задач. В менеджере освобождение session.busy и публикация
result теперь защищены одним lock: следующий инструмент не получает случайный 409.

LLM-прокси — отдельная точка с ключом. Модель задаётся серверной LLM_MODEL,
редиректы запрещены, TLS включён, тела ошибок провайдера не пересылаются.
Обращения к модели не повторяются автоматически. HTTP используется только для
внутренней тестовой модели; внешний провайдер требует HTTPS.

История и клиентские события — в RAM; JSONL-метаданные — в приватной tmpfs.
В них нет текстов файлов, diff, команд и сообщений. Закрытие удаляет сессию,
фикстуру и метаданные. Постоянную историю и политику хранения ещё предстоит выбрать
вместе со студентом. После падения харнеса его сандбоксы уберёт idle-таймер менеджера;
восстановления агентного цикла пока нет.

## Альтернативы

- Цикл внутри gateway: меньше процессов, но отклоняет структуру шаблона и смешивает
  входной транспорт с выполнением. Сохранили отдельный сервис из обсуждённой схемы.
- Отдельный finish_task: явное завершение, но дополнительный инструмент и правило
  для модели. Студент выбрал текст без tool_calls.
- Параллельные инструменты: быстрее независимые чтения, но сложнее подтверждения,
  порядок контекста и конфликты. Для первого цикла достаточно последовательности.
- Сохранять полный контекст на диск: удобно для replay, но оставляет копии файлов
  и требует выбора срока хранения и очистки. Сейчас только метаданные.

## Последствия и проверка

Первая консоль работает на учебной фикстуре и показывает diff/команду, затем ждёт
ответа пользователя. GUI, mount и автоматическое переподключение CLI не реализованы.
Дешёвое слово «готово» модели не заменяет программную проверку БАФ.
Сменные харнесы конфигурацией A-4.3 ещё не подключены.

Проверено агентом: unit-тесты цикла и транспорта, сценарный LLM в отдельном Compose,
настоящие Docker-операции и CLI. Реальная Qwen прочитала фикстуру и завершила задачу
текстом за два обращения; на текущем Desktop потребовался временный DNS-снимок.
Глобальные настройки Docker не менялись, IP не встроен в сервис/образ.
