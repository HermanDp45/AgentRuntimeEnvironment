# ADR-0011. Offline-БАФ и нормализация таблиц

Дата: 2026-11-11. Статус: accepted для локального прототипа.
Связано: ADR-0008, ADR-0010; C2-05, C2-06.

## Решение

Пользователь выбрал нормализацию таблиц своей новой БАФ: преобразование схемы,
дат и чисел, затем обнаружение неоднозначных значений. Это одна операция над
представлением данных. Три задачи B9 проверяют результат JSON и сохранность CSV.

Для больших и нетекстовых фикстур пользователь выбрал временную папку с
существующим монтированием. Раннер экспортирует только копию учебной фикстуры,
закрывает сессию, останавливает экспорт и удаляет копию. Локальный режим ограничен
проверенной связкой macOS + Docker Desktop. Он не доказывает работу разных машин.
Для cp1251 добавлен явный параметр существующих инструментов: ADR-0012.

Smoke использует явные сценарные ответы в testing-образе LLM-прокси. Это вручную
подготовленный replay, не записи реальной модели и не замер её качества. Задачи,
харнес, подтверждения, сандбокс и чекеры исполняются по-настоящему. Исходные ответы
лежат в services/llm-proxy/testing/baf_replay.json. В production-образе их нет.
Скрытые проверки сгенерированного кода выполняются в отдельном сандбоксе менеджера,
а не в Python-процессе хоста. Для этого раннеру нужен локальный адрес менеджера.

## Альтернативы

- Живая модель в CI: нестабильность сети, секреты и расход; оставлена для отдельных
  прогонов качества после выбора разрешённой модели.
- Unit-mock всего раннера: быстрее, но не проверяет путь через сервер и файловые
  операции. Сохранён только для отдельных негативных сценариев.
- Бинарные файлы в обоих протоколах: потребовали бы новой схемы и миграции.
  Пользователь выбрал существующий mount.
- Своя БАФ проверки утверждений: обсуждалась; пользователь предпочёл таблицы.

## Последствия

make test-ci требует Docker и GUI-зависимости, подготовленные заранее. Подготовка
образов может обращаться к registry; тесты используют только локальный mock.
make test-unit оставлен для быстрой проверки без Docker. Native Linux mount и
удалённая машина требуют отдельной проверки; базовый UI в CI работает с mock.
Полный набор содержит 39 задач. Его сценарный replay проверяется отдельно через
mount; качество реальной пары измеряется отдельным модельным прогоном.
