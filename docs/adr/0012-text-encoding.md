# ADR-0012. Явная кодировка файловых инструментов

Дата: 2026-11-11. Статус: accepted. Связано: A-6, Б4.3, ADR-0010/0011.

## Контекст и решение

Курсовая Б4.3 требует изменить CSV в cp1251, сохранив кодировку и CRLF.
Пользователь согласовал добавление этой возможности в существующие инструменты.
ReadFile и WriteFile получают encoding: utf-8 по умолчанию или cp1251.
Обе JSON Schema обновлены из моделей. Компоненты развёртываются вместе:
смешивание старых и новых образов с явным encoding не поддерживается.

ReadFile декодирует байты явно. SHA вычисляется по исходным байтам, а не тексту.
Preview читает файл в кодировке предполагаемой записи. WriteFile строго кодирует
текст до публикации: неподдерживаемый символ даёт ошибку, исходник не меняется.
Переводы строк сохраняются, автоматического преобразования CRLF нет.
WebDAV передаёт байты; его протокол не изменён. Collect остаётся UTF-8, поэтому
нетекстовые/большие фикстуры полного БАФ проверяются на локальной временной папке.

## Альтернативы и последствия

- Угадывать кодировку: неоднозначно, можно незаметно испортить текст.
- Передавать произвольный base64: расширяет формат и ухудшает читаемость diff.
- Разрешить запись shell в mount: разрушает принятую границу подтверждения правок.

Выбран ограниченный список из двух кодировок. Лимит остаётся 64 КиБ байтов на файл.
Проверяется сохранность cp1251/CRLF и отказ до записи для непредставимого символа;
полный серверный путь проверяется задачей Б4.3 через mount.
