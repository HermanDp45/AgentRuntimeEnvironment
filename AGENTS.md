# Работа с репозиторием

Эти правила действуют для всего проекта.

- Пиши компактный, понятный код. Добавляй абстракции и зависимости под текущую задачу.
- Докстринги и комментарии нужны там, где объясняют неочевидное решение; держи их короткими.
- Документацию пиши по-русски, имена в коде — по-английски. Убирай воду и повторения.
- Не выдавай запланированное за работающее. README должен соответствовать проверенному коду.
- Перед изменением прочитай относящиеся к нему задачи и ADR.
- После содержательного изменения обнови `docs/action-log.md`: зачем, что изменено, чем проверено.
- В `TASKS.md` отмечай выполнение и проверку раздельно. Для проверки укажи человека/агента
  и свидетельство. Проверка агентом не означает проверку человеком.
- Значимые архитектурные решения записывай в `docs/adr/`: альтернативы, причины, последствия.
  Непроверенные варианты имеют статус «предложено». Устаревшие ADR сохраняй как superseded.
- Перед завершением запускай `make test-ci`; изменения контейнеров проверяй через Compose.
  Новые тесты должны проверять поведение и реальные риски, а не повторять реализацию.
- Закрепляй зависимости в `uv.lock`, образы и внешние компоненты — по версии и ревизии.
- Храни исходные результаты экспериментов вместе с конфигурацией и командой воспроизведения.
  Не коммить секреты, содержимое пользовательских папок, веса и большие бинарники без LFS.
- Коммиты и push разрешены в рамках задачи. Используй существующую Git-идентичность владельца,
  без `Co-authored-by` и дополнительной атрибуции агенту. Не переписывай историю без запроса.
- Не добавляй пустые сервисы, фиктивные проверки и документацию ради объёма.
