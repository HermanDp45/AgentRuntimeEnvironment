# WebDAV и FUSE на учебной папке

Дата: 2026-11-11. Агент проверял на Mac arm64 и Linux arm64 внутри Docker Desktop,
Engine 27.3.1. На Mac — rclone v1.75.2. Тестовые Linux-образы закреплены в
скриптах по digest. Данные, пароли и ключи одноразовые.

```bash
docker pull rclone/rclone:1.75.2
uv run --frozen --offline python -m tests.infra.webdav_probe
uv run --frozen --offline python -m tests.infra.webdav_tunnel_probe
```

SSH-проба использует уже скачанный Linux-образ kicbase v0.0.51 с OpenSSH.
Оба образа должны быть доступны локально. Версии и digest указаны в коде.
Проба поднимает sshd с временными ключами на localhost. Пароль WebDAV проверяет
rclone. FUSE-помощник получает /dev/fuse и право на mount, читатель и писатель
работают с UID 10001. Оба временных контейнера удаляются.

- [FUSE](fuse.json). Подтверждены правки в обе стороны, замена файла через временный
  файл, отказ в режиме ro и чтение после перезапуска экспорта. При остановке
  WebDAV чтение вернуло ошибку примерно за 5 с. При обрыве с открытой записью
  замена завершилась ошибкой и исходный файл сохранился. Эта проба использует
  host-gateway Docker Desktop, чтобы обойти недоступность DNS-имени внутри контейнера.
- [SSH](ssh.json). Чтение и запись прошли по цепочке Mac → обратный SSH →
  Linux FUSE. Клиент проверял одноразовый ключ SSH-хоста.
- Проверка границ на одноразовой папке показала, что фильтр rclone оказался
  недостаточным для защиты .git, а запись через симлинк изменила файл вне папки.
  Доступ к произвольной папке через экспериментальный CLI исключён.
- [make test-ci](test-ci.txt). Обычные тесты проекта отдельно от экспериментальных.

Отдельная Linux-машина, Windows, защита пользовательских папок и подключение
FUSE-пути в основную сессию агента остаются открыты.
