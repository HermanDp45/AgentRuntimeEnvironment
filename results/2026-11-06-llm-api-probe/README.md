# Проверка временного LLM API · 2026-11-06

Проверял агент Codex. Провайдер и модель предоставлены студентом; проверка допуска
модели к официальным БАФ не проводилась. Серверная интеграция и харнес ещё отсутствуют.

- Endpoint: `https://inference.airi.net/v1/chat/completions`.
- Модель: `Qwen/Qwen3-235B-A22B-Instruct-2507`.
- Два синтетических запроса, temperature 0, max_tokens 8 и 128.
- Python 3.13.15, httpx2 2.16.0, Mac arm64; точные версии — в `uv.lock`.
- Ключ находится только в локальном `.env`, права 600, файл исключён из Git.

## Результаты

В [response.json](response.json) сохранены запросы без заголовков авторизации,
ответы API, длительности и usage. Оба запроса получили HTTP 200:

1. Ответ на текстовое сообщение — `OK`.
2. При `tool_choice=auto` модель вернула вызов `get_service_port` с аргументами
   `{"service":"orders"}`. Функция не исполнялась, результат инструмента модели не возвращался.

Всего: 185 входных и 23 выходных токена. Это проверка формата и доступа,
не оценка качества агента или скорости модели.

## TLS

Первая попытка через urllib остановилась на проверке цепочки сертификатов,
до получения HTTP-ответа. Она сохранена в [initial-tls-error.json](initial-tls-error.json).
DNS и HTTPS отдельно проверены без ключа; системный curl проходит проверку TLS,
стандартный Python сообщает self-signed certificate in certificate chain.

Для повторной проверки использован уже закреплённый httpx2: на macOS его httpcore2
использует системное хранилище сертификатов через truststore. TLS не отключался,
перенаправления не разрешены; системные сертификаты и настройки не изменялись.

## Воспроизведение

После `make setup` указать локально в `.env` корневой адрес `LLM_PROVIDER_URL`
и `LLM_API_KEY`. Ключ не передаётся аргументом командной строки.

```bash
uv run --frozen --env-file .env python services/llm-proxy/probe.py results/api-check.json
```

Потребуется действующий ключ и сеть. Утилита возвращает 0 только при двух успешных
проверках и пишет отдельный JSON; API-запросы не входят в `make test-ci`.
Offline-проверки проекта и отсутствие ключа в Git-кандидатах проверены отдельно:
[verification.txt](verification.txt).
