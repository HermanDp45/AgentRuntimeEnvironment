# Инфраструктурные тесты

Работают два уровня: прямой HTTP к настоящему сандбоксу и весь путь
консоль/gateway → харнес → LLM-прокси → mock LLM → сандбокс.

```bash
make up-test
make test-agent
make test-lifecycle
make down-test
```

Это отдельный проект Compose на loopback 18080/18081. Прокси получает тестовый ключ,
mock LLM задаёт сценарий, инструменты выполняются в настоящем Docker. make test-agent
перед запросами проверяет mock URL и не обращается к реальному API.
После установки зависимостей и сборки образов внешняя сеть не нужна.

check_lifecycle.py проверяет SIGKILL, startup cleanup и штатный shutdown локального
менеджера без активных пользовательских сессий; сохраняет его фактический порт
при пересоздании и оставляет менеджер остановленным.

На обычном сервере без mock: make test-infra запускает только прямые тесты сандбокса;
тесты харнеса явно пропускаются. make test-ci тоже явно пропускает Docker-сценарии.

Сейчас проверяются approval/diff/отказ, ошибка команды в контексте модели, один result,
идемпотентность, SSE resume, история, cancel, лимиты сандбокса, read-only, сеть,
изоляция сессий, CLI и метаданные без текстов. Unit-тесты отдельно моделируют сбои
POST/SSE и неподтверждённую отмену. Это не полная реализация C2-05: остаются обрывы
mount, падение харнеса с восстановлением, GUI, allowlist-сеть, fork bomb и нагрузочные замеры.
