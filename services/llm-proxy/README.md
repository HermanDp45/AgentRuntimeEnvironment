# llm-proxy

Статус: сервис не реализован. `probe.py` отдельно проверяет доступ к временному API.

Будет единственной точкой обращения к API модели: ключ хранится в этом сервисе
и не попадает в сандбокс. Адрес модели, её версия и конфигурация фиксируются для эксперимента.
Переменные `LLM_PROVIDER_URL` (корневой адрес провайдера) и `LLM_API_KEY` хранятся
локально в `.env`. Gateway их не получает. Временная модель — `Qwen/Qwen3-235B-A22B-Instruct-2507`;
проверены текстовый ответ и выдача tool_call, без исполнения инструмента.

## Проверка доступа

После `make setup` и локальной настройки `.env`:

```bash
uv run --frozen --env-file .env python services/llm-proxy/probe.py results/api-check.json
```

Это два сетевых запроса с лимитами ответа 8 и 128 токенов. Используется уже закреплённый
dev-пакет httpx2; TLS проверяется, перенаправления запрещены, ключ в отчёт не записывается.
Проверка не входит в offline CI. [Исходные результаты](../../results/2026-11-06-llm-api-probe/README.md).

Серверная реализация и Dockerfile появятся здесь после согласования устройства харнеса
и прокси. Задача C1-02 — в [TASKS.md](../../TASKS.md).
