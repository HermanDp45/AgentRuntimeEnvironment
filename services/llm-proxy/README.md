# LLM-прокси

Работает отдельный FastAPI-сервис. Харнес отправляет историю и схемы инструментов
на /v1/chat/completions. Прокси добавляет серверные model и Authorization,
обращается к настроенному провайдеру и возвращает ответ.

Только этот контейнер получает LLM_API_KEY. В gateway, харнес и сандбокс ключ
не передаётся. Ошибки провайдера возвращаются без его тела ответа и заголовков;
из успешного JSON убирается случайное вхождение самого ключа.
Перенаправления запрещены, TLS проверяется. Автоматических повторов запросов нет.

Настройки в локальном .env: LLM_PROVIDER_URL — корень API, LLM_API_KEY,
LLM_MODEL — имя модели. По умолчанию используются https://inference.airi.net и
Qwen/Qwen3-235B-A22B-Instruct-2507. Внешний провайдер требует HTTPS;
HTTP разрешён только для локального тестового mock-llm/localhost.

GET /health не вызывает модель: показывает доступность сервиса и configured.
Без ключа сервер запускается, но запрос к модели получает 503 api_key_missing.
Это позволяет проверять установку без API-доступа.

Исходники — src/llm_proxy/app.py; Dockerfile с target production собирает сервис.
Target testing дополнительно включает testing/mock_llm.py: он используется только
из tests/infra/compose.yml, не является настоящей моделью и не оценивает качество агента.

## Проверки

make up-test и make test-agent запускают весь путь с тестовой моделью и отдельным
тестовым credential. Реальный ключ для них не используется, запросы к провайдеру не идут.

probe.py остаётся отдельной проверкой доступности провайдера с Mac:

```bash
uv run --frozen --env-file .env python services/llm-proxy/probe.py results/api-check.json
```

Два синтетических платных запроса, без исполнения инструмента.
Проверка уже была [сохранена](../../results/2026-11-06-llm-api-probe/README.md).
Полный read-only сценарий через gateway — services/harness/probe.py.

В основном Compose для llm-proxy задан dns_opt: [use-vc], DNS через TCP.
Это устраняет обнаруженную недоступность публичного UDP/53 в текущей VPN-сети.
Сервис использует имя провайдера и проверяет TLS, ручного IP в конфигурации нет.
Обычного make up достаточно; глобальные настройки Docker/VPN не менялись.
[Диагностика](../../results/2026-11-06-dns-investigation/README.md),
[проверка исправления](../../results/2026-11-06-dns-fix/README.md).
