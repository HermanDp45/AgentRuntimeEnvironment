# Харнес

Работает небольшой Python/FastAPI-сервис. Он получает задачу от gateway,
собирает историю, вызывает LLM-прокси и исполняет инструменты через сандбокс.

- src/agent_harness/loop.py — цикл, контекст, лимиты, обработка результатов.
- tools.py рядом — JSON-схемы read_file/write_file/run_command, проверка и diff.
- clients.py рядом — HTTP к прокси и менеджеру, SSE и восстановление наблюдения.
- runtime.py рядом — сессии, запуски, ожидание approval, cancel, JSONL-метаданные.
- app.py рядом — маршруты клиентского контракта, доступные через gateway.
- config.toml — действующие лимиты; Dockerfile — сборка сервиса.

Ответ модели без tool_calls завершает задачу. Чтение автоматическое;
каждая запись и команда требуют отдельного разрешения. При неподтверждённом исходе
операции сессия блокируется, чтобы повторный запрос не продублировал действие.

Сервис не получает API-ключ, Docker socket или пользовательскую папку.
Рабочая папка пока временная учебная фикстура. История в RAM, метаданные в tmpfs;
после закрытия сессии они удаляются. Долговечное хранение ещё не реализовано.

[Карта реализации и ограничения](../../docs/harness.md),
[контракты](../../contracts/README.md), [консольный запуск](../../client/README.md).

probe.py выполняет один реальный read-only сценарий на синтетическом файле через
запущенный gateway. Запись и команды отклоняет. Ключ для него не нужен в процессе
пробы: тот находится только в уже настроенном llm-proxy.

```bash
uv run --frozen --offline python services/harness/probe.py results/harness-read.json
```

Это отдельная платная API-проверка; в CI она не запускается и не является БАФ-бенчмарком.
